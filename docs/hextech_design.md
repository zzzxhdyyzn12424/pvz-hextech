> 全部数值见 `docs/hextech_values.md`

> 每株植物种下带随机海克斯，每个僵尸出场带随机海克斯。

## 0. 核心规则

### 每个对象随机 1~3 个（v0.7 改）

| 项 | 值 |
|---|---|
| 数量 | 每个植物 / 僵尸各自独立随机 `1~3` |
| 重复 | 同一对象身上不可重复（无放回抽样） |
| 上限 | 3 |

> 原本设计是「按波次 `min(wave+1, 3)`」。但实测 `Board+0x5568` 读到 **6725**，
> `Board+0x5564` 读到 **4**，两个都对不上 1-1 的波次，说明之前的判定有误。
> 在波次字段真正吃准之前，先用随机 1~3，代码里留了 `COUNT_MODE = "wave"` 开关。

### 词条不可重复

同一株植物 / 同一个僵尸身上，**不会出现两条相同的词条**。
抽取方式是「无放回抽样」（`random.sample`）。

### 池子分档（为后续扩展预留）

| 档位 | 颜色 | 状态 |
|---|---|---|
| 银色 | `#C0C8D0` | ✅ 本期 47 条全部是银色 |
| 金色 | `#F0B429` | ⏳ 以后加 |
| 棱彩 | `#B57BFF` | ⏳ 以后加 |

代码里词条对象统一带 `tier` 字段，抽卡时先按档位加权选档、再档内选条目。
现在只有银色池，权重 100%。

### 适用植物限定

部分词条只对特定类型开放：

- **输出植物**：豌豆射手 / 寒冰射手 / 双发 / 机枪 / 三线 / 裂荚 / 杨桃 / 西瓜 / 玉米炮 / 地刺 等
- **承伤植物**：坚果 / 高坚果 / 南瓜头 / 大蒜 / 花盆 等
- **带减速的植物**：寒冰射手 / 冰西瓜 / 冰豌豆 等

## 3. 架构：血量通道 + 原生防具通道

### 两条路，按效果性质选

| 通道 | 用于 | 做法 |
|---|---|---|
| **血量通道** | 增伤、免伤、DoT、回血、击杀奖励 | 每帧 diff 血量，少补或多扣 |
| **原生防具通道** | 僵尸护盾 | 直接写 `+0xD8/+0xDC/+0xE0`，游戏自己吸收 |

为什么护盾必须走防具通道：
- 血量通道是「事后回补」，50ms 一帧的窗口里漏掉的伤害就永远漏了；
- 原生护盾是「事前拦截」，所有伤害来源（豌豆、樱桃、大嘴花…）自动生效；
- 护盾贴图真的会长出来，玩家看得见，符合「防具」的直觉；
- 【电龙魂】写明「无视护甲」，它走 `_damage_zombie()` 直接写 `+0xC8`，天然穿盾，不用特判。

植物没有护甲字段（只有 `+0x40` 血量），所以植物的【山脉龙魂】仍然走血量通道回补。


### 关键洞察

血量是**唯一同时可读可写、且每次战斗交互都会变化**的字段。
所以不需要注入 DLL 挂钩子，只要每帧轮询：

```
每帧读所有僵尸的 +0xC8（血量）
  ↓
血量比上一帧少了 D → 说明刚被打了 D 点 → 这是一个"命中事件"
  ↓
根据该僵尸/攻击者的海克斯，决定要不要：
  · 把 D 补回去（免伤 / 护盾吸收）
  · 再扣 0.5D（伤害提升）
  · 给自己回 0.3D（渴血）
  · 把 0.4D 摊成 3 秒流血（死之舞）
  · 加 50 阳光（收集者，血量归零时）
```

**这样 38 条词条里有 26 条可以纯外挂实现**，不用碰游戏代码。

### 僵尸的「防具」字段（v0.6 新确认，护盾改走原生通道）

| 字段 | 偏移 | 说明 |
|---|---|---|
| 头盔当前血量 | `+0xD0` | 路障 / 铁桶 / 橄榄球头盔 |
| 头盔最大血量 | `+0xD4` | 用于算 1/3、2/3 破损贴图 |
| **护盾类型** | **`+0xD8`** | **0 = 没有盾；非 0 才会吸收伤害** |
| **护盾当前血量** | **`+0xDC`** | |
| 护盾最大血量 | `+0xE0` | 同上，算破损贴图 |

证据 —— `Zombie::TakeDamage`（`0x5317C0`）的完整流程：

```
0x531838  cmp dword ptr [esi+0xD8], 0    ; 护盾类型
0x53183F  je  0x531856                   ; 没盾 → 跳过
0x531841  test bl, 1                     ; 伤害标志 bit0 = 无视护盾
0x531844  jne 0x531856
0x53184A  call 0x530BC0                  ; TakeShieldDamage：扣 +0xDC，溢出继续
0x53184F  test bl, 2
0x531854  mov  eax, ebp                  ; bit1：还原成原始伤害
0x531856  test eax, eax / jle 返回
0x531866  call 0x530FE0                  ; TakeHelmetDamage：扣 +0xD0
0x531872  call 0x5312D0                  ; TakeBodyDamage：扣 +0xC8
```

**结论：护盾吸收是游戏自己算的，我们只要把三个字段写上，一帧都不用补血。**
头盔没有独立的「类型」字段（外观由僵尸类型 `+0x24` 决定），所以只能给本来就有头盔的僵尸补 `+0xD0`，
不能给普通僵尸凭空加路障 —— 但**护盾可以**，因为有 `+0xD8`。

`tools/hextech.py armortest <类型> <血量>` 可以现场试哪种护盾贴图最合适。

**最大血量不需要偏移**：对象第一次出现时血量必然是满的，记下来当基准即可。

### 波次字段：静态线索有了，但实测对不上（⏸ 搁置）

| 字段 | 静态推断 | 实测（1-1，两株豌豆） | 结论 |
|---|---|---|---|
| `Board+0x5550` | 关卡号（1..50） | `1` | ✅ 对得上 |
| `Board+0x5564` | 本关总波数 | `4` | ❓ 1-1 总波数不该是 4，存疑 |
| `Board+0x5568` | 当前波次 | `6725` | ❌ 显然不是波次 |

静态证据（仍然成立，只是语义解释错了）：
- `0x409339 mov eax,[edi+0x5550]; sub eax,1` → 夹在 `0..0x31` → `mov esi,[eax*4+0x6a34e8]`
  查一张 50 项的表 —— **50 正好是 PVZ 冒险模式的关卡数**，所以 `0x5550` = 关卡号这点很硬。
- `0x415B29 add dword ptr [esi+0x5568], 1` 是全 exe 唯一的自增点，
  后面紧跟 `call 0x413a70` / `0x413d00` / `0x414100`。

> ⚠ 坑：`0x424923 cmp [ecx+0x5568], 0xbb8` 看着像「波次 == 3000」，
> 其实 `ecx = [Board+4]`，是**另一个结构**的 +0x5568，别被误导。

#### 覆盖层的两个必踩的坑

1. **改完 `WS_EX_*` 必须 `SetWindowPos(SWP_FRAMECHANGED)`** —— Windows 会缓存窗口样式，
   不冲刷的话 `WS_EX_TRANSPARENT`（点击穿透）根本不生效。
2. **tk 的 `-transparentcolor` 会被后续 `SetWindowLongW` 冲掉** —— 必须在设完 exstyle 之后
   再显式补一次 `SetLayeredWindowAttributes(hwnd, colorkey, 0, LWA_COLORKEY)`。

#### 抓图自检（不开游戏也能验证）

- `PrintWindow(PW_RENDERFULLCONTENT)` 会把色键区渲染成**纯黑**，分不清「透明」和「黑色文字」；
  要保留色键必须用 `BitBlt`（`SRCCOPY`）。
- `hextech.py run --shot out.png --after 2.5 [--geom 800x600+60+60]` 跑 2.5 秒后把覆盖窗口
  自身内容存 PNG 再退出，`--geom` 可在游戏最小化时离线校验整张 800×600 布局。
- `tools/preview_compose.py <游戏截图> <覆盖层png> <输出> [左 上]` 按色键把覆盖层合成到
  游戏截图上，用来预览真实效果。

#### 游戏最小化 / 失焦

PVZ 一失焦就暂停，最小化后 `GetClientRect` 返回 `0×0`、`GetWindowRect` 返回 `-32000,-32000`。
处理：`IsIconic()` 为真时**隐藏覆盖层**（免得卡片飘在桌面上），但保留上次几何，
游戏恢复后下一帧立刻归位。**不主动唤醒游戏窗口。**

> 调试提示：暂停时内存里的对象全都「静止」，血量 diff / 位移观测 / 帧钟全为 0，
> 很容易被误读成「字段没生效」。上机验证前先看画面有没有「游戏暂停」墓碑。

### 3.6 僵尸移速：字段找到了，但外部改不动

**一句话**：移速字段是 `Zombie+0x34`，但 `Zombie::Update` 每帧把它夹回目标值，
所以只能改走坐标 `+0x2C` 补位移。完整推导与实测数据见 `docs/hextech_values.md` §3。

对象布局补充（僵尸）：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x08` / `+0x0C` | int | `mX` / `mY`，**只是镜像**，每帧由 float 坐标取整同步 |
| `+0x2C` / `+0x30` | float | **真实坐标 X / Y**，外部可写、游戏接受 |
| `+0x34` | float | 移速（每次 Update 的像素数），每帧被 `min(speed+0.01, target)` 夹回 |
| `+0x48` | int | 动画帧计数（1~9 循环），决定这一帧要不要推进位置 |
| `+0x60` | int | **帧钟，每秒 +100**，用它归一化可以消除帧率抖动 |
| `+0x11C` | float | 动画速率（默认 1.0），**不是移速**（早期误判过） |

关键函数：

| 地址 | 作用 |
|---|---|
| `0x524A70` | `Zombie::UpdateZombieSpeed`，按类型/状态往 `+0x34` 写速度常数 |
| `0x52947B` | 真正的移动段，`speed = min(speed+0.01, target)` 后 `posX += speed×k` |
| `0x52AC94` | Draw 里的位置插值，也读写 `+0x34`/`+0x2C`（早期误判为移动代码） |
| `0x679530` | double `0.01`，速度斜坡步长 |
| `0x679670` / `0x67966C` / `0x67963C` | float `0.23` / `0.12` / `0.45`，普通 / 减速 / 快速组速度 |

工具：`tools/pvzdis.py`（反汇编任意区间）、`tools/find_move.py`（扫写 `[reg+disp]`）、
`tools/probe_speed.py`（上机 A/B 验证倍率）。

### 3.7 植物攻速：真的多射豌豆

植物射击函数 `0x45F8A9`：

```asm
0x45F8A9  add  [esi+0x58], -1      ; 倒计时
0x45F8B3  jg   跳过
0x45F8BA  call 0x5af400            ; rand(0,15)
0x45F8BF  mov  ecx, [esi+0x5c]     ; ★ 射击间隔
0x45F8C2  sub  ecx, eax
0x45F8CA  mov  [esi+0x58], ecx     ; 重置倒计时
0x45F917  call 0x45ef10            ; ★ 生成豌豆
```

- `Plant+0x5C` = 射击间隔（帧），豌豆射手原生 150 帧（1.5 秒）。
- `Plant+0x58` = 当前倒计时，每帧 -1。
- 攻速 +X% 的实现：`+0x5C = round(原值 / (1+X))`。
- 游戏随后在更短周期调用 `0x45ef10`，**子弹由游戏自己生成**，弹道/命中/动画全部原生。
- 不会影响向日葵：只有输出植物能抽到灵巧/狂热者/羊刀。

**上机验证方式**：`tools/probe_shoot.py` 数 `+0x58` 的跳变次数，直接得到每秒开火数，
不用看伤害数字。`test` 模式同时回读 `+0x5C` 判断写入是否被游戏重算覆盖。
详见 `hextech_values.md` §3.5。
