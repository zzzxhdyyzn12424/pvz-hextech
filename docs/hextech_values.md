**泰坦的坚决**和植物版同名同效果，只是作用对象换成僵尸。按「本次受伤**前**」
的层数减伤，所以第一次挨打是全额，从第二次开始变硬。叠满 15 层后等效血量 ×4。
和【孤勇者】可以叠（50% × 75% → 87.5% 免伤，等效血量 ×8），
**没做互斥**：孤勇者要求 9 宫格没同伴，天然自带限制。

**水龙魂**是「受伤后」或「正在啃植物」两个条件**任一成立**就回血：

- 受伤后 3 秒内 → 回血（`last_hit` 由受伤检测写入）
- 1 秒内啃到过植物 → 回血（`last_bite` 在 `_zombie_attack` 里写入）
- 两个条件都不满足（脱战、也没在吃）→ 停止回血，累加器清零
- 满血时不回（不会溢出）

回血用**累加器**：30 帧/秒下 20 血/秒 = 0.67 血/帧，直接 `round` 会变成
每帧 +1，实际跑成 30 血/秒。所以攒够 1 点才写一次内存。

**男爵之手是光环**：场上只要有一只带这词条的僵尸，所有僵尸（包括它自己）
都吃 +50% 移速和 +50% 伤害。两只男爵**不叠加**（`self._baron` 是布尔值），
否则会失控。

**科学狂人 / 小小杀手互斥**：两条都是「缩体型 + 加速」，同时出现没有意义，
而且移速叠加会直接飞出屏幕。

## 3. 实现手法（含 v1.2 攻速 / 减速 / 移速结论）

因为**攻速 / 啃食间隔字段还没定位**，这几类效果用了等价手段：

| 需求 | 做法 | 差别 |
|---|---|---|
| **植物攻速 +X%** | 把 `Plant+0x5C`（射击间隔）改成 `原值 / (1+X)` | **真的多生成豌豆**，弹道、命中、动画全部走游戏原生流程 |
| **僵尸攻速 +X%** | 每次啃食额外造成 `伤害 × X` | 数值 DPS 等价，但**啃食动画不变** |
| **减速强化** | 观测僵尸每帧位移，再反向补掉其中 30% | 实际移速真的降了；**冰冻特效不变** |
| **移速 +X%** | 每帧往 `Zombie+0x2C`（float 坐标）补位移 | 位置真的变了，倍率精确；但**走路动画不变**，高速时有轻微滑步感 |
| **隔格啃植物** | 不移动僵尸，按 `Z_SCOPE_DPS` 直接扣目标植物血 | 效果等价，但僵尸不会走过去 |

### 3.1 为什么不能直接改移速字段（重要，别改回去）

僵尸的移速字段是 `Zombie+0x34`（float），`Zombie::UpdateZombieSpeed @ 0x524A70`
按「类型 + 状态」往里写速度常数（`0x679670`=0.23、`0x67966C`=0.12、`0x67963C`=0.45 …）。
看起来外部改它就能调速，**但实际上没用**，因为 `Zombie::Update @ 0x52947B` 每帧都做：

```asm
0x0052947B  fld  dword ptr [esi+0x34]   ; 当前速度
0x0052947E  fadd qword ptr [0x679530]   ; + 0.01  ← 斜坡步长
0x00529484  fld  dword ptr [esp+8]      ; 目标速度（本帧现算）
0x00529488  fcom st(1)
0x00529491  fstp st(1)                  ; 高于目标 → 直接取目标
0x0052949F  fst  dword ptr [esi+0x34]   ; 写回
0x005294BC  fstp dword ptr [esi+0x2c]   ; posX += 速度 × 系数
```

即 `speed = min(speed + 0.01, target)`。外部把 `+0x34` 写大，下一帧立刻被夹回 `target`。

上机 A/B 实测（同一只僵尸，用 `Zombie+0x60` 帧钟归一化）：

| 做法 | 位移 |
|---|---|
| 基准 ×1 | 19.5 px / 游戏秒 |
| `+0x34` ×2 | 20.2 px / 游戏秒 ← **没变** |
| `+0x34` ×3 | 12.3 px / 游戏秒 ← **更慢**（夹回过程占了斜坡） |

读报僵尸之所以能提速，是因为它改的是游戏自己的状态机（`target`），外部改不了。

### 3.2 正确的做法：补位移

`Zombie+0x2C` 是真正的位置（float），外部写入游戏完全接受、不会回弹
（实测一次性前移 20px，0.6 秒后总位移 34.2 = 我们写的 20 + 自然走的 14.2），
`+0x08 mX` 每帧由它取整同步。所以移速加成 = 每帧补一点位移。

**倍率用自适应，不用固定系数。** 因为「`+0x34` → px/秒」要乘一个「真正推进位置的
Update 占比」，这个占比不是常数：僵尸自由行走时约 0.97，在啃食/停顿时只有 0.5 左右。
固定系数会让「+100% 移速」实际只有 +50%~+90%。

自适应做法：每帧观测僵尸自己的位移速率 `obs`（`prev_x` 记的是补完后的坐标，
所以不需要再减自己补的量），再补 `obs × bonus × dt`。
好处是任何状态下倍率都准，而且僵尸啃植物时它自己不动，我们也不推它。

上机验证（`tools/probe_speed.py`，6 轮基准 + 3 轮加速，+100%）：

```
基准 0.11776 px/tick  →  加速 0.23836 px/tick  =  2.02×（期望 2.00×）
```

单元测试断言的倍率全部为精确值：逃跑计划 **×3.0**、孤勇者 **×2.0**、
家园卫士 **×2.0**（挨打后回到 ×1.0）、练腿日 **×1.5**。

### 3.3 练腿日的「免疫减速」

冰冻会让 `Zombie+0x11C`（动画速率）从 `1.0` 掉到 `0.5` 左右，用它当减速探针：

```
未减速速度 = obs_rate / anim_rate
需要补的量 = 未减速速度 × (1 + bonus − anim_rate)
```

`anim_rate == 1.0` 时 `1 + bonus − 1 = bonus`，公式自动退化成普通加成，
**所以探针判错也不会多补**。探针区间取 `0.30 ≤ ar < 0.98`，区间外一律按没减速处理。

单元测试覆盖：被冰冻时基准速度掉到 0.5 倍，练腿日把它拉回 ×1.5 的未减速速度
（`chilled_leg / chilled_base = 3.0`）。

### 3.4 攻速与冰寒（v1.2 补齐）

#### 植物攻速：直接缩短射击间隔

`0x45F8A9` 是植物射击更新函数，逻辑非常干净：

```asm
0x45F8A9  add  dword ptr [esi+0x58], -1   ; 射击倒计时 -1
0x45F8B3  jg   跳过                        ; 还没到 0
0x45F8BA  call 0x5af400                    ; rand(0, 15) 抖动
0x45F8BF  mov  ecx, dword ptr [esi+0x5c]   ; ★ 射击间隔
0x45F8C2  sub  ecx, eax                    ; 间隔 - 抖动
0x45F8CA  mov  dword ptr [esi+0x58], ecx   ; 重置倒计时
0x45F917  call 0x45ef10                    ; ★ 真正生成豌豆
```

所以：

```
Plant+0x58 = 当前倒计时（每帧 -1）
Plant+0x5C = 射击间隔（帧）
新间隔 = round(原间隔 / (1 + 攻速加成))
```

改 `+0x5C` 之后，游戏会在更短的周期内自己调用 `0x45ef10` 生成豌豆 ——
**豌豆数量、弹道、命中、动画全部是游戏原生的**，不是补伤害。

- **灵巧**：`+0x5C` 缩到 `1/1.25`，150 帧 → 120 帧。
- **狂热者**：`+0x5C` 缩到 `1/1.15`，150 帧 → 130 帧；双倍伤害仍单独判定。
- **羊刀**：按归因命中次数叠层，每层 +1%，上限 +100%；间隔随之逐次缩短。
- 间隔下限 1 帧，避免极端叠层写出 0 导致每帧开火。
- 只对输出植物生效；向日葵等生产植物的 `+0x5C` 不会被改，产阳光速度不受影响。

#### 僵尸攻速：仍是等量增伤

僵尸的啃食间隔字段尚未定位，所以【灵巧】【狂热者】【孤勇者】【屹立不倒】
仍用「每次啃食额外造成等量伤害」模拟 DPS。差别是啃食动画不变。
如果后续定位到僵尸啃食计时字段，可以同样改成真实缩短间隔。

**冰寒**走坐标补位移，而不是改游戏减速字段：

```
每帧观测 dx = 当前 posX − 上一帧补完后的 posX
额外回推 = −dx × 0.30          # 等效速度 ×0.70
持续 3 秒，每次命中刷新
```

- 只有 `SLOW_PLANTS`（寒冰射手 / 冰西瓜）且带 `p_chill` 的植物命中才触发。
- **练腿日直接免疫**，连 `chill_until` 都不设置。
- 回推后必须同步 `st.prev_x`，否则移速加成会把回推量误当成僵尸自己的速度。

**瞄准镜**按距离判定：近身（≤70px）走游戏原生啃食；70~160px 是隔 1 格，
70~240px 是隔 2 格，按 `Z_SCOPE_DPS` 直接扣目标植物血。

### 3.5 v1.6 的两个取舍（如实说明）

#### 体型缩小：改的是碰撞盒，不是绘制

【科学狂人】【小小杀手】要「体型缩小（套小僵尸大麻烦）」。

**做到的部分**：`Zombie+0x10 / +0x14`（`O_W` / `O_H`）按 `0.60` 压小，
宽 50 → 30、高 110 → 66。每帧维护（读 2 写 2），因为游戏可能在某些状态重算宽高。

**没做到的部分**：**视觉大小不变**。PVZ 僵尸的绘制尺寸来自 reanim 动画自带的
`mScaleX/mScaleY`，僵尸对象里没有一个可以直接写的 float 缩放字段。已扫过 `.text` 里
`disp` 落在 `0x100~0x170` 的全部 float 写入，只有 `0x11C`（动画速率）是每帧会动的，
其余都不是缩放用途。

要做到真视觉缩小，需要再定位 `Zombie::Draw` → `mBodyReanim` → `Reanimation::mScaleX`
这条链，属于下一阶段的工作。

#### 小丑学院：有自爆，没有召唤

【小丑学院】原文是「死亡后召唤一个小丑僵尸在自身所在位置自爆」。

**做到的部分**：死亡瞬间在自身位置触发一次范围爆炸（半径 90、伤害 1800），
对范围内每株植物各结算一次。1800 这个数是照着「把一格清空」定的——
普通植物 300 血、坚果墙 4000 血，所以爆炸范围内除了坚果墙/高坚果基本全灭，
而坚果墙也会掉将近一半。

**没做到的部分**：**没有真的生成一只小丑僵尸**。生成僵尸要走 `Board::AddZombie`，
需要 `CreateRemoteThread` 远程调用游戏代码，或者手工构造整个 Zombie 对象
（含 reanim 指针、音效、状态机初始化）。两条路任何一步错都会直接崩游戏，
风险远大于收益。爆炸这个**玩法核心**保留了，召唤的**视觉**没有。

### 3.6 相关工具

| 工具 | 用途 |
|---|---|
| `tools/probe_speed.py` | 上机 A/B 验证移速倍率（用游戏帧钟归一化，不受帧率抖动影响） |
| `tools/probe_shoot.py` | 上机验证「真的多射豌豆」：数 `+0x58` 的跳变次数，直接得每秒开火数 |
| `tools/pvzdis.py` | 反汇编任意地址区间 / 反查 call 来源（逆向用） |
| `tools/find_move.py` | 全 `.text` 扫描「写某个 `[reg+disp]`」的指令 |

#### 上机验证植物攻速（`probe_shoot.py`）

不需要看伤害数字，直接数游戏自己触发了几次开火。原理就是 `+0x58` 的跳变：

```
上一次读数 <= 8（倒计时快归零）  且  这一次 > 40（被重置成大数）  →  开了一枪
```

```bat
:: 先开游戏、进关卡、种一株豌豆射手，保持游戏窗口在前台
python tools\probe_shoot.py show        :: 看 +0x58 / +0x5C 现值
python tools\probe_shoot.py count 12    :: 不改内存，纯观测 12 秒（基准应 ~0.67 发/秒）
python tools\probe_shoot.py test 12     :: 写入 120 帧，观测 12 秒，自动还原（应 ~0.83 发/秒）
```

`test` 模式同时回答两个问题：

1. **`+0x5C` 会不会被游戏每帧重算覆盖** —— 观测结束时回读该字段，若仍等于写入值就说明不会。
2. **是不是真的多射了** —— 实测发/秒 ÷ 基准发/秒 应 ≥ 1.12，否则只是数值补偿。

`test` 结束会自动把 `+0x5C` 还原成原值，不改存档、不改 exe。

> PVZ 失焦或最小化会自动暂停，此时 `+0x58` 冻结不动，计数为 0。看到「几乎没开火」先检查前台。

## 4. 平衡提醒

1. **逃跑计划 + 山脉龙魂互斥**后，逃跑计划的单卡强度是「50% 血时白送 100% 血量护盾」，
   等效血量 100% → 200%，是全表最强的一张。
2. **装甲冲击**按「头盔+护盾」算，如果僵尸同时带山脉龙魂（30% 盾），
   铁桶僵尸的爆发会非常夸张 —— 因为护盾也算进去了。
3. **星界躯体**的 -30% 伤害是**乘算前的减法**，和「重量级打手」的固定加成叠加时，
   会先减 30% 再加固定值，所以对高血量僵尸收益偏低。
4. **屹立不倒 + 渴血**同时存在时吸血会叠两层（一层固定 30%，一层按已损失 70%），
   血量见底时几乎打不死。
