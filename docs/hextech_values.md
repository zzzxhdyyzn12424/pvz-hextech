**大腕的击退是「整格」不是「单只」**：设计原文是「把命中的那一格的僵尸击退一格」，
所以实现里先算命中僵尸所在的列（`col = (x - 40) / 80`，草坪第 0 格左沿 40px、每格 80px），
再把这**同一行、同一列**区间里的所有僵尸一起推 80px。只推挨打的那一只时，
一堆僵尸叠在一起，后面的照样贴在植物脸上，等于没击退。
对应参数 `LAWN_XMIN=40` / `LAWN_CELL_W=80` / `LAWN_COLS=9`。

**大腕的实际手感**：100 Update/秒下 1200 帧 = **12 秒一发**（原版 150 帧 = 1.5 秒）。
单发伤害 ×6，纯 DPS = 6 × 1/8 = 原版的 **0.75 倍**——略低于原版，
换来的是「一发打掉一大截血 + 整格后退一格」。这是有意的：纯 DPS 换功能。

历次调整：
- 攻速：v1.6 `0.75`（×4，6 秒）→ v1.6.4 `0.875`（×8，12 秒）
- 伤害：v1.6 `1.00`（×2）→ v1.6.5 `5.00`（×6）
想回退就改这两个数：`P_BIGPEA_SLOW`（0.75 = 6 秒 / 0.5 = 3 秒 / 0 = 原版）、
`P_BIGPEA_DMG`（1.00 = ×2 / 0 = 原版）。

**泰坦巨人的阳光**：按原版成本表再扣一份（豌豆射手 100 → 总共 200）。
阳光不够时夹到 0，不会出负数。同一株只扣一次（`titan_sun_done` 标记）。

**巨人杀手的算法**：`ratio = min(2.0, z_hp_max / 10 × 0.01)`。
普通僵尸 200 血 → +20%；铁桶 1370 → +137%；巨人 3000 → 封顶 +200%。

**泰坦的坚决**和植物版同名同效果，只是作用对象换成僵尸。按「本次受伤**前**」
的层数减伤，所以第一次挨打是全额，从第二次开始变硬。叠满 15 层后等效血量 ×4。
和【孤勇者】可以叠（50% × 75% → 87.5% 免伤，等效血量 ×8），
**没做互斥**：孤勇者要求 9 宫格没同伴，天然自带限制。

**水龙魂**是「受伤后」或「正在啃植物」两个条件**任一成立**就回血：

- 受伤后 3 秒内 → 回血（`last_hit` 由受伤检测写入）
- 1 秒内啃到过植物 → 回血（`last_bite` 在 `_zombie_attack` 里写入）
- 两个条件都不满足（脱战、也没在吃）→ 停止回血，累加器清零
- 满血时不回（不会溢出）

回血用**累加器**：30 帧/秒下 20 血/秒 = 0.67 血/帧，直接 `round` 会变成
每帧 +1，实际跑成 30 血/秒。所以攒够 1 点才写一次内存。

**男爵之手是光环**：场上只要有一只带这词条的僵尸，所有僵尸（包括它自己）
都吃 +50% 移速和 +50% 伤害。两只男爵**不叠加**（`self._baron` 是布尔值），
否则会失控。

#### 终极不可阻挡：怎么算「免疫控制」

触发条件只有一个：**这只僵尸第一次掉血**。之后 `cc_until = now + 10`，
每只僵尸一辈子只触发一次（`st.fired` 里记 `unstoppable`），
10 秒过了再挨打也不会给第二次。

窗口内免疫的是这三条通道，正好覆盖 mod 里全部「控制」：

| 控制来源 | 平时 | 免疫时 |
|---|---|---|
| 【冰寒】（减速植物 + 冰寒词条） | `chill_ratio = 0.30`，额外压 30% 移速 | 直接不吃，已挂上的立刻清掉 |
| 原生冰冻 / 减速（寒冰射手、冰西瓜） | 游戏把 `+0x11C` 压到 0.5，走得慢 | 按「没被控时的速度」补位移，照走 |
| **【黄油】**（玉米投手） | 完全定住：不走、也不能啃 | **走得动**（按基准速度推），但**仍然啃不了** |
| **【寒冰菇】冰冻** | 全屏定住：不走、也不能啃 | 同上 |
| 【大腕】整格击退 | 一格内所有僵尸一起被推 80px | 从整格击退里剔除，推不动 |

**「控制」其实有两层，这词条只免疫了第一层**：

| 层 | 内容 | 状态 |
|---|---|---|
| **移动层** | 能不能往前走 | ✅ 免疫。黄油 / 冰冻期间游戏一帧都不推它，我们就按基准速度把它推过去 |
| **行动层** | 能不能啃植物 | ❌ 不免疫。黄油和冰冻是游戏自己的状态机（`mButtered` / `mFrozen` 一类的标志位），**没定位到安全可写的偏移**，硬改会让 reanim 错乱 |

所以一只被黄油糊住、又开了【终极不可阻挡】的僵尸，会**一边保持黄油动画、
一边慢慢往前走**——走到植物跟前还是啃不了，等黄油时间结束才恢复啃食。
这是这一版能做到的边界，不是漏做。

**为什么不能复用移速加成那套自适应逻辑**：那套是「观测僵尸自己走了多少，
再按比例补」。僵尸被冻住时它压根不动，观测值是 0，`0 × 任何比例 = 0`，
等于没免疫。所以免疫期间换成「算期望位移，差多少补多少」：

```
参考速率 = max(进窗口前观测到的速率, +0x34 × 100)
期望位移 = 参考速率 × dt × (1 + 移速加成)
补的量   = 期望位移 − 游戏这一帧实际走的
```

`+0x34` 是「每次 Update 前进多少像素」，乘 100 Hz 就是 px/游戏秒
（普通僵尸 0.23 × 100 = 23 px/s，和实测的 `Z_BASE_SPEED_PX` 对得上）。
**这里不能乘 `Z_MOVE_DUTY`(0.45)** —— 那个系数只给 `obs_rate` 的初始猜测用，
几帧内就被低通纠正；拿它算期望位移会少补一半（v1.6.6 的 bug，v1.6.7 修）。

两个**故意不推**的情况：

- **正在啃植物**（`last_bite` 0.5 秒内）：啃食时本来就不动，推了会把它从植物嘴边拽走。
- **前面 50px 有植物**：它停住是因为被植物挡住，不是因为被控。不判这条的话，
  被冻住的僵尸会被一路推进植物身体里。

**诚实的局限**：视觉上它**仍然显示冰冻动画**（游戏在放冰冻的 reanim，我们没有
清冻结状态标志——那个标志游戏自己管，硬改容易出动画错乱）。所以你会看到
一只「看起来冻着、但一直在往前走」的僵尸。移动、啃食、击退免疫都是真的。

**科学狂人 / 小小杀手互斥**：两条都是「缩体型 + 加速」，同时出现没有意义，
而且移速叠加会直接飞出屏幕。

## 3. 实现手法（含 v1.2 攻速 / 减速 / 移速结论）

因为**攻速 / 啃食间隔字段还没定位**，这几类效果用了等价手段：

| 需求 | 做法 | 差别 |
|---|---|---|
| **植物攻速 +X%** | 把 `Plant+0x5C`（射击间隔）改成 `原值 / (1+X)` | **真的多生成豌豆**，弹道、命中、动画全部走游戏原生流程 |
| **僵尸攻速 +X%** | 每次啃食额外造成 `伤害 × X` | 数值 DPS 等价，但**啃食动画不变** |
| **减速强化** | 观测僵尸每帧位移，再反向补掉其中 30% | 实际移速真的降了；**冰冻特效不变** |
| **移速 +X%** | 每帧往 `Zombie+0x2C`（float 坐标）补位移 | 位置真的变了，倍率精确；但**走路动画不变**，高速时有轻微滑步感 |
| **隔格啃植物** | 不移动僵尸，按 `Z_SCOPE_DPS` 直接扣目标植物血 | 效果等价，但僵尸不会走过去 |

### 3.1 为什么不能直接改移速字段（重要，别改回去）

僵尸的移速字段是 `Zombie+0x34`（float），`Zombie::UpdateZombieSpeed @ 0x524A70`
按「类型 + 状态」往里写速度常数（`0x679670`=0.23、`0x67966C`=0.12、`0x67963C`=0.45 …）。
看起来外部改它就能调速，**但实际上没用**，因为 `Zombie::Update @ 0x52947B` 每帧都做：

```asm
0x0052947B  fld  dword ptr [esi+0x34]   ; 当前速度
0x0052947E  fadd qword ptr [0x679530]   ; + 0.01  ← 斜坡步长
0x00529484  fld  dword ptr [esp+8]      ; 目标速度（本帧现算）
0x00529488  fcom st(1)
0x00529491  fstp st(1)                  ; 高于目标 → 直接取目标
0x0052949F  fst  dword ptr [esi+0x34]   ; 写回
0x005294BC  fstp dword ptr [esi+0x2c]   ; posX += 速度 × 系数
```

即 `speed = min(speed + 0.01, target)`。外部把 `+0x34` 写大，下一帧立刻被夹回 `target`。

上机 A/B 实测（同一只僵尸，用 `Zombie+0x60` 帧钟归一化）：

| 做法 | 位移 |
|---|---|
| 基准 ×1 | 19.5 px / 游戏秒 |
| `+0x34` ×2 | 20.2 px / 游戏秒 ← **没变** |
| `+0x34` ×3 | 12.3 px / 游戏秒 ← **更慢**（夹回过程占了斜坡） |

读报僵尸之所以能提速，是因为它改的是游戏自己的状态机（`target`），外部改不了。

### 3.2 正确的做法：补位移

`Zombie+0x2C` 是真正的位置（float），外部写入游戏完全接受、不会回弹
（实测一次性前移 20px，0.6 秒后总位移 34.2 = 我们写的 20 + 自然走的 14.2），
`+0x08 mX` 每帧由它取整同步。所以移速加成 = 每帧补一点位移。

**倍率用自适应，不用固定系数。** 因为「`+0x34` → px/秒」要乘一个「真正推进位置的
Update 占比」，这个占比不是常数：僵尸自由行走时约 0.97，在啃食/停顿时只有 0.5 左右。
固定系数会让「+100% 移速」实际只有 +50%~+90%。

自适应做法：每帧观测僵尸自己的位移速率 `obs`（`prev_x` 记的是补完后的坐标，
所以不需要再减自己补的量），再补 `obs × bonus × dt`。
好处是任何状态下倍率都准，而且僵尸啃植物时它自己不动，我们也不推它。

上机验证（`tools/probe_speed.py`，6 轮基准 + 3 轮加速，+100%）：

```
基准 0.11776 px/tick  →  加速 0.23836 px/tick  =  2.02×（期望 2.00×）
```

单元测试断言的倍率全部为精确值：逃跑计划 **×3.0**、孤勇者 **×2.0**、
家园卫士 **×2.0**（挨打后回到 ×1.0）、练腿日 **×1.5**。

### 3.3 练腿日的「免疫减速」

冰冻会让 `Zombie+0x11C`（动画速率）从 `1.0` 掉到 `0.5` 左右，用它当减速探针：

```
未减速速度 = obs_rate / anim_rate
需要补的量 = 未减速速度 × (1 + bonus − anim_rate)
```

`anim_rate == 1.0` 时 `1 + bonus − 1 = bonus`，公式自动退化成普通加成，
**所以探针判错也不会多补**。探针区间取 `0.30 ≤ ar < 0.98`，区间外一律按没减速处理。

单元测试覆盖：被冰冻时基准速度掉到 0.5 倍，练腿日把它拉回 ×1.5 的未减速速度
（`chilled_leg / chilled_base = 3.0`）。

### 3.4 攻速与冰寒（v1.2 补齐）

#### 植物攻速：直接缩短射击间隔

`0x45F8A9` 是植物射击更新函数，逻辑非常干净：

```asm
0x45F8A9  add  dword ptr [esi+0x58], -1   ; 射击倒计时 -1
0x45F8B3  jg   跳过                        ; 还没到 0
0x45F8BA  call 0x5af400                    ; rand(0, 15) 抖动
0x45F8BF  mov  ecx, dword ptr [esi+0x5c]   ; ★ 射击间隔
0x45F8C2  sub  ecx, eax                    ; 间隔 - 抖动
0x45F8CA  mov  dword ptr [esi+0x58], ecx   ; 重置倒计时
0x45F917  call 0x45ef10                    ; ★ 真正生成豌豆
```

所以：

```
Plant+0x58 = 当前倒计时（每帧 -1）
Plant+0x5C = 射击间隔（帧）
新间隔 = round(原间隔 / (1 + 攻速加成))
```

改 `+0x5C` 之后，游戏会在更短的周期内自己调用 `0x45ef10` 生成豌豆 ——
**豌豆数量、弹道、命中、动画全部是游戏原生的**，不是补伤害。

- **灵巧**：`+0x5C` 缩到 `1/1.25`，150 帧 → 120 帧。
- **狂热者**：`+0x5C` 缩到 `1/1.15`，150 帧 → 130 帧；双倍伤害仍单独判定。
- **羊刀**：按归因命中次数叠层，每层 +1%，上限 +100%；间隔随之逐次缩短。
- **大腕**：`+0x5C` **放大 8 倍**，150 帧 → 1200 帧（详见下面「反方向也验证过」）。
- 间隔下限 1 帧，避免极端叠层写出 0 导致每帧开火。

#### 反方向也验证过：调大 `+0x5C` 真的会少射

「调小能多射」只证明了提速有效，不能推出「调大能少射」——游戏完全可能
把间隔夹回上限。所以用 `probe_shoot.py slow` 单独验了一遍（2026-10-29 实测，
场上同时有带大腕的和原版的豌豆射手）：

| `+0x5C` | 理论间隔 | 实测间隔 | 开火后 `+0x58` 被重置成 |
|---|---|---|---|
| **600**（大腕） | 6.00 s | — | **587 / 591 / 593 / 598** |
| **375**（大腕 + 羊刀 60 层） | 3.75 s | 3.61 s | 369 |
| **150**（原版） | 1.50 s | 1.40~1.44 s | 142~149 |
| **130**（狂热者） | 1.30 s | 1.23 s | 127 |
| **107**（灵巧 + 羊刀） | 1.07 s | 1.00 s | 103 |

**关键证据是「重置值」**：`+0x58` 只会每帧 -1，一个曾经被重置到 150 的倒计时
永远涨不回 587。场上读到 587~598，说明游戏确实把倒计时重置到了 `600 - rand(0,15)`，
也就是**它按 600 帧在等，没有夹回原版 150**。

> 帧率是 **100 Update/秒**，不是 30。所以 150 帧 = 1.5 秒一发（0.67 发/秒），
> 600 帧 = 6 秒一发。用 30 算会得出「20 秒一发」的错误期望。

> **v1.6.4 起大腕的间隔是 1200 帧（12 秒）**，上表是 v1.6 时按 600 帧实测的。
> 机制没变（都是「游戏按 `+0x5C` 的帧数等」，重置值 = `间隔 - rand(0,15)`），
> 但 1200 这一档**没有重新上机量**——改这个值时游戏没开。要复核的话：
> 种一株带大腕的豌豆射手，`python tools/probe_shoot.py slow 40`，
> 期望重置值落在 1185~1199、两次开火间隔约 12 秒。

**顺带一个平衡事实**：v1.6.5 起大腕单发伤害 ×6、频率 1/8，纯 DPS = **0.75 倍**原版。
它是个「用 DPS 换整格击退 + 单发爆发」的词条，不是纯加强。

**一个没实测到的情况**：地刺 / 地刺王（type 21 / 46）不发射子弹，它们的 `+0x5C`
按理不是「射击间隔」（大概率是 0）。`_plant_shoot_apply` 里有
`1 < cur < 100000` 的守卫，读到 0 会直接返回、不写内存——所以最坏结果是
「这两株拿到大腕只吃伤害 ×6 + 击退，攻速部分无效」，不会写出脏数据。
（写这条时场上没有地刺，属于按代码推的，没有实测。）
- 只对输出植物生效；向日葵等生产植物的 `+0x5C` 不会被改，产阳光速度不受影响。

#### 为什么倍率不会「越重启越离谱」（v1.6.5 修的 bug）

改 `+0x5C` 是**持续性**的：我们写进去的值会一直留在游戏内存里。
而启动器关掉重开时，**游戏进程并没有退出**——于是那些已经被改过的植物，
会把「改后的值」当成原版值重新读进来，再乘一次倍率：

| 情况 | 第一次 | 重启一次 | 重启两次 |
|---|---|---|---|
| 大腕（×8） | 1200（12 秒） | 9600（96 秒，等于不射） | 76800 |
| 灵巧（÷1.25） | 120（1.2 秒） | 96 | 76（0.76 秒，接近无敌） |

往大偏是「大腕彻底不射」，往小偏就是**「那一行无敌」**——正是最危险的方向。

修法：原版只有 150 / 300 两档射击间隔，所以落在 `[140, 400]` 之外的读数
一定是 mod 写的，用 `cur × mult` 就能精确剥回原值（多剥几层兼容已偏过多次的）。
剥不出来时按 150 / 300 就近吸附。实现在 `Engine._native_shoot_base()`。

**怎么自己确认生效了**：游戏里跑

```
python tools/probe_shoot.py audit
```

会列出每一株的 `+0x5C`、折算秒数、以及判定（原生 / 已降速 ×N / 已提速 ×N）。
大腕生效时那一行应该显示 **`已降速 ×8.0`**、12.00 秒/发。

#### 僵尸攻速：仍是等量增伤

僵尸的啃食间隔字段尚未定位，所以【灵巧】【狂热者】【孤勇者】【屹立不倒】
仍用「每次啃食额外造成等量伤害」模拟 DPS。差别是啃食动画不变。
如果后续定位到僵尸啃食计时字段，可以同样改成真实缩短间隔。

**冰寒**走坐标补位移，而不是改游戏减速字段：

```
每帧观测 dx = 当前 posX − 上一帧补完后的 posX
额外回推 = −dx × 0.30          # 等效速度 ×0.70
持续 3 秒，每次命中刷新
```

- 只有 `SLOW_PLANTS`（寒冰射手 / 冰西瓜）且带 `p_chill` 的植物命中才触发。
- **练腿日直接免疫**，连 `chill_until` 都不设置。
- 回推后必须同步 `st.prev_x`，否则移速加成会把回推量误当成僵尸自己的速度。

**瞄准镜**按距离判定：近身（≤70px）走游戏原生啃食；70~160px 是隔 1 格，
70~240px 是隔 2 格，按 `Z_SCOPE_DPS` 直接扣目标植物血。

### 3.5 v1.6 的两个取舍（如实说明）

#### 体型缩小：改的是碰撞盒，不是绘制

【科学狂人】【小小杀手】要「体型缩小（套小僵尸大麻烦）」。

**做到的部分**：`Zombie+0x10 / +0x14`（`O_W` / `O_H`）按 `0.60` 压小，
宽 50 → 30、高 110 → 66。每帧维护（读 2 写 2），因为游戏可能在某些状态重算宽高。

**没做到的部分**：**视觉大小不变**。PVZ 僵尸的绘制尺寸来自 reanim 动画自带的
`mScaleX/mScaleY`，僵尸对象里没有一个可以直接写的 float 缩放字段。已扫过 `.text` 里
`disp` 落在 `0x100~0x170` 的全部 float 写入，只有 `0x11C`（动画速率）是每帧会动的，
其余都不是缩放用途。

要做到真视觉缩小，需要再定位 `Zombie::Draw` → `mBodyReanim` → `Reanimation::mScaleX`
这条链，属于下一阶段的工作。

#### 小丑学院：有自爆，没有召唤

【小丑学院】原文是「死亡后召唤一个小丑僵尸在自身所在位置自爆」。

**做到的部分**：死亡瞬间在自身位置触发一次范围爆炸（半径 90、伤害 1800），
对范围内每株植物各结算一次。1800 这个数是照着「把一格清空」定的——
普通植物 300 血、坚果墙 4000 血，所以爆炸范围内除了坚果墙/高坚果基本全灭，
而坚果墙也会掉将近一半。

**没做到的部分**：**没有真的生成一只小丑僵尸**。生成僵尸要走 `Board::AddZombie`，
需要 `CreateRemoteThread` 远程调用游戏代码，或者手工构造整个 Zombie 对象
（含 reanim 指针、音效、状态机初始化）。两条路任何一步错都会直接崩游戏，
风险远大于收益。爆炸这个**玩法核心**保留了，召唤的**视觉**没有。

| `tools/probe_speed.py` | 上机 A/B 验证移速倍率（用游戏帧钟归一化，不受帧率抖动影响） |
| `tools/probe_shoot.py` | 上机验证「真的多射豌豆」：数 `+0x58` 的跳变次数，直接得每秒开火数 |
| `tools/probe_seed.py` | 种子银行 / 盲盒卡：`dump` 打印卡槽、`defs` 打印植物定义表、`watch` 观测冷却、`blind` 现场试盲盒 |
| `tools/pvzdis.py` | 反汇编任意地址区间 / 反查 call 来源（逆向用） |
| `tools/find_move.py` | 全 `.text` 扫描「写某个 `[reg+disp]`」的指令 |

#### 上机验证植物攻速（`probe_shoot.py`）

不需要看伤害数字，直接数游戏自己触发了几次开火。原理就是 `+0x58` 的跳变：

```
上一次读数 <= 8（倒计时快归零）  且  这一次 > 40（被重置成大数）  →  开了一枪
```

```bat
:: 先开游戏、进关卡、种一株豌豆射手，保持游戏窗口在前台
python tools\probe_shoot.py show        :: 看 +0x58 / +0x5C 现值
python tools\probe_shoot.py count 12    :: 不改内存，纯观测 12 秒（基准应 ~0.67 发/秒）
python tools\probe_shoot.py test 12     :: 写入 120 帧，观测 12 秒，自动还原（应 ~0.83 发/秒）
```

`test` 模式同时回答两个问题：

1. **`+0x5C` 会不会被游戏每帧重算覆盖** —— 观测结束时回读该字段，若仍等于写入值就说明不会。
2. **是不是真的多射了** —— 实测发/秒 ÷ 基准发/秒 应 ≥ 1.12，否则只是数值补偿。

`test` 结束会自动把 `+0x5C` 还原成原值，不改存档、不改 exe。

> PVZ 失焦或最小化会自动暂停，此时 `+0x58` 冻结不动，计数为 0。看到「几乎没开火」先检查前台。

## 3.7 盲盒卡（v1.7）

> 「可以增加植物盲盒卡片吗，就像其他的改版那样」—— 用户需求
> 选择：**新增一张盲盒卡** + 随机范围 **全部 49 种植物**

### 结论先说

**没有真的新增第 11 张卡，而是把某一个已有卡槽变成「盲盒」。**

原因：真·新增卡需要三件事同时成立，缺一不可 ——
① 种子银行数组扩容（`SeedPacket mSeedPackets[10]` 之后紧跟 `mNumPackets`，
越界就写坏计数）；② 一张新卡面（要往 `main.pak` 塞 reanim 并改
`gReanimDefs` 表）；③ 一个能画出「?」的 `ReanimationType`。
这三步都在 `.data`/资源层，任何一步错都是启动即崩，而这个 mod 的
架构是「只读写内存、不注入代码」，做不了 ② ③。

**但盲盒的玩法核心保住了**：卡面固定、种下去随机。下面是把这件事做成的关键。

### 内存地基（全部静态反汇编，逐条可复核）

| 地址 | 指令 | 含义 |
|---|---|---|
| `0x40B1DA` | `mov ecx, [ebp+0x144]` | **`SeedBank = Board->mSeedBank`** |
| `0x40B1E0` | `mov [ecx+0x24], eax` | `SeedBank+0x24` = `mNumPackets` |
| `0x40B1F6` | `lea esi, [ebx+edx+0x28]` | 第一张卡在 `SeedBank+0x28` |
| `0x40B204` | `add ebx, 0x50` | `sizeof(SeedPacket) = 0x50` |
| `0x40B20A` | `cmp ebx, 0x320` | `0x320 / 0x50 = 10`，最多 10 张 |
| `0x489AC0` | `SeedBank::RemoveSeed(idx)` | 同样按 `+0x28 + idx*0x50` 定位，交叉验证 |
| `0x489ACD` | `lea eax, [eax+esi+0x5c]` | = `packet+0x34` |
| `0x489AD4` | `cmp dword ptr [eax], -1` | 空槽的 `mPacketType` 是 `-1` |
| `0x489B57` | `mov [esi+0x34], edi` | `SetPacketType`：**`mPacketType`** |
| `0x489B5A` | `mov [esi+0x38], edx` | `mImitaterType` |
| `0x488F7D` | `mov [edi+0x28], eax` | 冷却 = `gPlantDefs[type].mRefreshTime` |

### SeedPacket 结构（`0x50` 字节）

| 偏移 | 字段 | 说明 |
|---|---|---|
| `+0x00` | `gLawnApp` | GameObject 指纹（自检用） |
| `+0x04` | `Board` | GameObject 指纹（自检用） |
| `+0x08` | `mX` | 卡面左上角 X（屏幕坐标） |
| `+0x0C` | `mY` | 卡面左上角 Y |
| `+0x28` | `mRefreshCounter` | 冷却剩余帧数，0 = 冷却完毕 |
| `+0x34` | **`mPacketType`** | ★ 种什么就看这个 |
| `+0x38` | `mImitaterType` | 只有变身茄子卡（48）会用 |
| `+0x48` | `mActive`（byte） | 1 = 可以点 |
| `+0x49` | `mCooling`（byte） | 1 = 冷却中 |
| `+0x4C` | `mUses` | 用了几次，只增不减 → 用来检测「刚种下」 |

### 为什么改 `+0x34` 不会连带改卡面

这是整个方案成立的前提，值得单独说清楚：

1. 卡面（reanim）只在 `SeedPacket::SetPacketType`（`0x489B50`）里建一次，
   关卡开始时 `SeedBank` 初始化循环调用它，之后**再没被调用过**。
2. 玩家种下植物 → `0x488EC0`（`SeedPacket::Deactivate`）里只做三件事：
   `mUses++`、`mCooling = 1`、`mRefreshCounter = gPlantDefs[mPacketType].mRefreshTime`。
   **它没有重建卡面**，只是用 `+0x34` 去查冷却表。
3. `Board::AddPlant`（`0x40D120`）种什么，读的也是 `+0x34`。

所以 `+0x34` 从关卡开始就与「画什么」脱钩了 —— **画的是开局那张卡，
种的是我们每帧写进去的随机值**。这就是盲盒。

### 怎么触发随机

`Engine._tick_blindbox()`，三种模式（`Engine.BLINDBOX_MODE`）：

| 模式 | 触发时机 | 手感 |
|---|---|---|
| `"charge"`（默认） | 卡槽从「冷却中」变成「可用」的**那一帧**，以及 `mUses` 变化时 | 卡面 / 光标预览稳定，一次充能只随机一次 |
| `"use"` | `mUses` 每 +1 | 种下后立刻换，下次拿起时已经是新植物 |
| `"always"` | 只要可用就每帧随机 | 最盲，但光标预览会逐帧闪 |

默认 `BLINDBOX_SLOT = 0`（第 1 格）；设成 `-1` 就是最后一格。
`BLINDBOX_POOL` 默认 `range(49)`，`BLINDBOX_EXCLUDE` 可以排掉需要水面 /
需要花盆的植物（例如 `(16, 19, 43)`）。

抽到 **变身茄子（48）** 时会自动补一个随机 `mImitaterType`，
否则种下去是个没有目标的空壳。

### 安全阀

`Game.scan_seedbank()` 每次都做三项自检，**任何一项不过就返回空列表，
整段逻辑直接不干活**（宁可不做也不乱写内存）：

1. `mNumPackets` 必须落在 `1..10`
2. 每张卡的 `+0x00`/`+0x04` 必须等于 `gLawnApp` / `Board`
   —— 这条最硬，等于用 GameObject 的对象头当指纹
3. `mPacketType` 必须是 `-1` 或 `0..48`

### 上机验证（`probe_seed.py`）

```bat
python tools\probe_seed.py dump       :: 打印整个种子银行，核对偏移
python tools\probe_seed.py defs       :: 打印 gPlantDefs（成本 / 冷却 / 攻速）
python tools\probe_seed.py watch 15   :: 只读观测 0 号卡 15 秒，看三个标志位的语义
python tools\probe_seed.py blind 30   :: 每 0.5 秒换一种，你去种，看种出来是不是卡面那种
```

`blind` 是判定性实验：

- **种出来 ≠ 卡面** → 卡面定死，盲盒成立，方案收工
- **种出来 = 卡面** → 卡面每帧跟着 `+0x34` 重建，得改成「只在拿起瞬间写」

### 已知取舍

- **占了一个卡槽**：玩家选的第 1 张卡会变成盲盒。想换格子改 `BLINDBOX_SLOT`。
- **卡面不是「?」**：盖的是覆盖层画的一个紫色 `?` 角标 + 冷却条，不是游戏原生美术。
- **`mActive` / `mCooling` 的语义是静态推的**，还没上机确认；
  即使推错也不会失效 —— `"charge"` 模式还有 `mUses` 变化这条兜底。

## 4. 平衡提醒

1. **逃跑计划 + 山脉龙魂互斥**后，逃跑计划的单卡强度是「50% 血时白送 100% 血量护盾」，
   等效血量 100% → 200%，是全表最强的一张。
2. **装甲冲击**按「头盔+护盾」算，如果僵尸同时带山脉龙魂（30% 盾），
   铁桶僵尸的爆发会非常夸张 —— 因为护盾也算进去了。
3. **星界躯体**的 -30% 伤害是**乘算前的减法**，和「重量级打手」的固定加成叠加时，
   会先减 30% 再加固定值，所以对高血量僵尸收益偏低。
4. **屹立不倒 + 渴血**同时存在时吸血会叠两层（一层固定 30%，一层按已损失 70%），
   血量见底时几乎打不死。
