# 怎么让别人玩到「PVZ 海克斯版」

> 本文回答一个问题：这东西现在只在我自己电脑上能跑，怎么发给别人？
> 最后更新：2026-10-30

---

## 0. 先认清它是什么

海克斯版**不是**一个改过的游戏文件，而是**一个挂在游戏旁边的程序**：

```
玩家电脑上：
    PlantsVsZombies.exe   ← 原版游戏，一个字节都没改
            ↑
            │ 运行时读写内存（Plant+0x5C、Zombie+0x2C、gLawnApp…）
            │
    PVZ海克斯版.exe        ← 我们发的就是这个
```

这个形态决定了三件事，绕不过去：

| 事实 | 后果 |
|---|---|
| 偏移量是从 **1.0.0.1051 中文版** 逆向出来的 | 玩家必须是这个版本，换版本会改错内存 |
| 需要读别人进程的内存 | 部分杀软会把它当木马 |
| 覆盖层是挂在游戏窗口上的透明窗口 | 游戏全屏独占时会被挡住，得切窗口模式 |

**所以「下载即玩」的整合包做不到**——那等于分发游戏本体，超出免费同人的边界，
也不该做。玩家必须自备游戏。

### 0.1 它到底动了什么？（可逐条核对）

一句话结论：**纯外置。游戏本体一个字节都不改，进程里也不插一行代码。**

| 动作 | 做没做 | 代码证据 |
|---|---|---|
| 改 `PlantsVsZombies.exe` 文件 | ❌ 没做 | 全仓库没有对 exe 的写文件操作 |
| 改 `main.pak` / `LawnStrings.txt` 等资源 | ❌ 没做 | 没有 pak 写入路径 |
| DLL 注入 / 远程线程 | ❌ 没做 | 无 `CreateRemoteThread`、无 `LoadLibrary` 注入 |
| API Hook / 内联补丁（改游戏机器码） | ❌ 没做 | 无 `SetWindowsHookEx`，不写 `.text` 段 |
| 模拟键鼠替你操作 | ❌ 没做 | 无 `SendInput` / `mouse_event` / `keybd_event` |
| 读游戏状态 | ✅ 做了 | `ReadProcessMemory` |
| 写游戏里的**数值字段** | ✅ 做了 | `WriteProcessMemory`，共 19 处，全部指向**堆上的对象**（植物 / 僵尸 / 卡槽 / Board） |
| 画界面 | ✅ 做了 | 另开一个 `WS_EX_LAYERED + WS_EX_TRANSPARENT` 的透明窗口叠在游戏上，点击穿透 |

关键点在于「写哪儿」。19 处写操作全部落在游戏运行时**新建的对象**上：

```
Plant  +0x40/+0x44   血量 / 血量上限
Zombie +0xC8         血量
Zombie +0xD8..0xE0   护盾三件套
SeedPacket +0x34     卡面植物类型（盲盒卡就靠这个）
Board  +0x144→…      种子银行内的卡槽
```

这些都是 `new` 出来的堆内存，**不是代码段、不是静态数据表、不是资源**。
所以：

- 关掉海克斯程序 → 下一帧游戏就按原版数值跑，**不需要还原任何东西**；
- 游戏崩溃 / 断电 → 内存本来就没了，**不存在坏档**（PVZ 存档只记关卡进度）；
- 唯一会留下痕迹的是**游戏自己的正常存档**（打了哪一关），和原版行为一致。

发布时这句话可以直接写进说明：「不修改游戏文件，关闭即还原，删掉文件夹不留残留。」
这比任何免责声明都管用。

#### 怎么自证没改游戏文件

玩家（或者你自己）随时可以用一行命令核对原版 exe 的 MD5：

```bat
certutil -hashfile PlantsVsZombies.exe MD5
```

1.0.0.1051 中文版的正确值是 `2422b3d75601bcf8592177455417b9ac`。
对不上就说明 exe 被动过——但**不一定是海克斯版动的**，见下面这条。

> ⚠️ 本机实测记录（2026-10-30）：开发机上的 exe 确实与原始备份差 **1 个字节**，
> 位置文件偏移 `0x3158F`（VA `0x43158F`），`75`（jne）被改成了 `EB`（jmp）。
> 这是早期工具 `tools/autocollect.py`（自动收集阳光）干的，**不是海克斯版**。
> `main.pak` 与 `main.pak.orig` 的 MD5 完全一致，资源没被动过。
> 想要一份干净的游戏，把 `PlantsVsZombies.exe.orig` 改回 `PlantsVsZombies.exe` 即可。

## 1. 四条技术路线，海克斯版选了 A

别人的改版基本都改本体，这不是错觉。改本体本身分三层，难度递增：

| 路线 | 做法 | 能做到什么 | 代价 |
|---|---|---|---|
| B. 改 `main.pak` | 替换贴图 / `reanim` / `LawnStrings.txt` | 只换外观和文字 | 零风险，但做不了任何逻辑。唐诗版的 pak 就是这类 |
| C. 打 exe 补丁 | 改机器码（本机那个 `75→EB` 自动收阳光就是） | 改判定、改数值、开关功能 | 每改一处要手写汇编 + 找洞；必须分发改过的 exe |
| **D. DLL 注入 + hook** | 写 dll，注入后挂钩游戏函数 | **新植物、新僵尸、新行为** —— 融合版的杂交体只可能在这一层 | 要逆向每个函数签名，钩错就崩，C++ 工具链 |
| **A. 运行时内存 mod** | 现在这套，Python/ctypes 读写进程内存 | 改数值 / 改位置 / 改类型号，**全部 47 条词条** | 加不了新植物新僵尸，改不了行为 |

### 为什么海克斯版不走 D

**这个仓库其实已经走过 D，而且代码还在**：`behavior/` 下 2351 行 C++ ——
DLL 注入器、`hook.h`（内联 hook 框架）、`aob.cpp`（特征码扫描）、`ballistic.cpp`（弹道），
外加一个完整的「唐诗射手」规格（射偏十次原地爆炸的状态机都写完了）。
编译通过、离线自测 23/23 全过，**但从没成功注入过游戏**，卡在两处：

1. `behavior/src/aob_patterns.h` 里 `AOB_PLANT_UPDATE` / `AOB_ZOMBIE_UPDATE` 是空字符串；
2. 更麻烦的是原先认定的「豌豆更新」`0x520AC0` 被证伪 —— 它是开火逻辑，
   而且整条调用链被 `cmp [mApp+0x7F8], 0x2B` 门住，冒险模式根本走不到。
   实测「三条钩子零命中」就是这个原因，不是特征码抄错了。

所以 A 不是「更干净所以更好」，是**在「只加词条」这个目标下更划算**：

| 维度 | A（外置） | D（DLL） |
|---|---|---|
| 加一条词条 | 几十行 Python 读写字段 | 一个 hook 点：逆向签名 → 找插入位置 → 存寄存器 → 写汇编 |
| 写错了 | 数值不对，看一眼覆盖层就知道 | 游戏直接崩，改一次重启一次 |
| 调试 | 改完即生效 | 编译 → 注入 → 重启 → 挂调试器 |
| 杀软 | 读写内存，中等误报 | 注入 + 远程线程，高误报 |
| 版权 | 不碰游戏文件 | 改 exe 等于分发盗版；dll 稍好 |

A 路线的额外好处：**不碰玩家的任何文件**。关掉程序，游戏立刻恢复原样。
这在发布时是个很好的卖点，也降低了玩家的信任门槛。

### 但天花板是硬的

| 想做的事 | A 能不能 | 原因 |
|---|---|---|
| 加新植物 / 新僵尸 | ❌ | `SeedType` `0..51` 全占；`gReanimDefs` 144 条排满 |
| 改植物行为 | ❌ | 行为是 `.text` 里 **516 处**散落的 `cmp [reg+0x24], <type>`，不是跳转表 |
| 新美术 / 新动画 | ❌ | 只能借用现有 reanim |
| 大肥鱼那种「新玩法」 | ⚠️ 借壳 | 借原植物贴图 + 我们自己的血量/范围伤害逻辑，外观不变 |

**分水岭**：能不能用「血量通道 + 范围伤害 + 位置改写」表达出来。
能，外置就够了；不能，就必须回 `behavior/` 走 D。
真要做融合版那种东西，D 是唯一的路，没有第二条。

## 2. 已经做好的东西

### 2.1 版本指纹校验（`tools/version_check.py`）

为什么不用 md5：本项目自己就给 exe 打过「自动收阳光」单字节补丁
（文件偏移 `0x3158F`，`0x75 → 0xEB`），md5 立刻变。用 md5 会把
「版本对但打过补丁」的玩家全部误杀。

改用 **4 处代码段指纹**，全部匹配才放行：

| VA | 字节 | 含义 |
|---|---|---|
| `0x44E969` | `a3 c0 9e 6a 00` | `mov [0x6A9EC0], eax` ← gLawnApp = new LawnApp |
| `0x407CA9` | `68 00 70 05 00` | `push 0x57000` ← sizeof(Board) = 356352 |
| `0x45F8A9` | `83 46 58 ff` | `add [esi+0x58],-1` ← 植物射击倒计时 |
| `0x45F8BF` | `8b 4e 5c` | `mov ecx,[esi+0x5c]` ← 读射击间隔 |

这四处都在代码段、与玩法无关，普通补丁不会动；换版本则必然对不上。

实测：`1.0.0.1051 中文版 + 自动收阳光补丁` → 4/4 通过，并正确提示「检测到已知补丁」。

### 2.2 一键启动器（`tools/launcher.py`）

玩家侧流程：

```
双击
 → 找游戏（运行中的进程 → 上次记住的路径 → 程序同目录 → 弹框让玩家选）
 → 校验版本
 → 通过 → 拉起覆盖层，显示热键说明
 → 不通过 → 一句人话说明怎么办，绝不硬上
```

几个细节：

- 校验通过但游戏没开 → 提示「先开游戏再双击」，而不是抛异常
- 记住路径存在同目录 `launcher.json`，只存路径，不联网
- `--diag` 输出诊断信息（Python 版本、是否管理员、进程、路径、校验结果），
  玩家反馈问题时让他整段复制，能省掉大量来回
- 打包版启动时把控制台切到 UTF-8，避免中文乱码

### 2.3 打包脚本（`tools/make_release.py`）

```
python tools/make_release.py
```

产出两个包：

| 包 | 内容 | 用途 |
|---|---|---|
| `PVZ_Hextech_v1.6.7.zip` | `PVZ海克斯版.exe`（约 29 MB）+ 使用说明 + 版本要求 | 主推，零门槛 |
| `PVZ_Hextech_v1.6.7_src.zip` | `tools/*.py` + `启动.bat` + 说明 | 杀软拦截时的兜底，玩家可审计每一行 |

> 上传到 GitHub Release 时资产名必须是 **ASCII**：GitHub 的 API 会把
> `name` 参数里的非 ASCII 字符整段剥掉（`PVZ海克斯版_v1.6.7.zip` 会变成
> `PVZ._v1.6.7.zip`）。本地构建产物仍叫中文名，上传时改个名即可。

**为什么两个都发**：exe 版要读别人进程内存，PyInstaller 打包的程序尤其容易
被杀软误判。源码版让玩家能自己看代码，是化解「你是不是木马」质疑最有效的方式。

exe 打包参数里特意加了 `--noupx`——UPX 压缩壳会显著提高误报率。

## 3. 实际发布步骤

### 3.1 打包

```bat
cd C:\Users\33854\Documents\默认项目\pvz-mod-kit
.venv\Scripts\python.exe tools\make_release.py
```

产物在 `build\release_hextech\` 下。

### 3.2 自测（每次发包前必做）

1. 把 zip 解压到**另一个目录**（模拟玩家环境，不要在原项目里测）
2. 开游戏 → 进 1-1 → 种一株豌豆射手
3. 双击 exe → 应看到「版本校验通过」→ 覆盖层出现
4. 按 F7 / F8 / F9 / F10 各试一次
5. 关掉 exe → 游戏应无异常
6. 故意把 exe 改个名字再跑 → 应提示「版本校验失败」，不能硬上

### 3.3 发布页要写清楚的四件事

1. **本包不含游戏本体**，需要自备《植物大战僵尸》1.0.0.1051 中文版
2. 版本怎么查：右键 exe → 属性 → 详细信息，文件大小约 3,007,800 字节
3. 杀软报毒怎么办：加白名单，或用源码版
4. 游戏要**窗口模式**（全屏独占时覆盖层会被挡住，按 Alt+Enter 切）

第 1 条写在标题下面第一行，别藏在小字里——这是最容易被骂的点。

### 3.4 版本号

`tools/make_release.py` 里的 `DEFAULT_VERSION`，或用 `--version 1.3.1` 覆盖。
建议和 `docs/hextech_values.md` 的版本对齐。

## 4. 风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| 杀软误报 / 直接删除 | 🔴 高 | ① `--noupx` ② 提供源码版 ③ 发布页写清楚 ④ 可以去微软提交误报申诉 |
| 玩家版本不对导致崩溃 | 🔴 高 | 已用 4 处指纹硬拦截，不通过不启动 |
| 玩家游戏全屏，看不到覆盖层 | 🟡 中 | 说明里写 Alt+Enter；启动时也打印一次 |
| 玩家把 mod 放错目录 | 🟢 低 | 启动器会自动找同目录 + 支持 `--exe` 记住路径 |
| OpenProcess 失败 | 🟡 中 | 提示右键管理员运行；`--diag` 里会显示是否管理员 |
| 有人二次打包去卖 | 🟡 中 | 免费同人，发布页声明；源码版反而能证明来源 |
| 覆盖层被别的置顶窗口盖住 | 🟢 低 | 已用 `make_clickthrough` + topmost；极端情况让玩家关掉别的置顶软件 |

## 5. 还没做的（按价值排序）

1. **英文原版 1.0.0.1051 是否兼容** —— 代码段可能一致，但没实测。
   如果兼容，受众会大一圈。需要找一份英文原版跑一次 `--diag`。
2. **游戏内首次启动提示** —— 现在热键只在控制台打印，玩家可能没看见。
   可以在覆盖层顶部加一行「按 F8 看详情」的浮层，几秒后淡出。
3. **词条说明面板** —— 现在 `panel` 模式要单独开窗口。
   如果玩家想知道「羊刀到底怎么叠」，需要更友好的图鉴。
4. **错误上报** —— `--diag` 是手动的。可以加个「一键生成反馈包」按钮，
   把诊断信息 + 最近日志打成 txt。
5. **自动更新检查** —— 分发渠道定了再说，现在过早。

---

## 6. 一句话总结

> 把 `tools/make_release.py` 跑一遍，得到两个 zip；
> 发布页第一行写「不含游戏本体，需自备 1.0.0.1051 中文版」；
> 玩家解压双击，启动器自己校验版本、自己找游戏、自己拉起覆盖层。

剩下的都是体验优化，不影响「别人能玩」。
