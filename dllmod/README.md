# dllmod —— 进程内版海克斯（改本体路线）

> 目标：让海克斯版以**改版**的形态存在，而不是「游戏 + 一个外挂程序」。
> 玩家把两个文件丢进游戏目录，双击游戏，海克斯就在里面。
> 最后更新：2026-10-30

---

**里程碑 1 已通过**：代理 DLL 能被游戏加载，代码在游戏进程内跑起来，能读到 `gLawnApp`。

## 为什么代理 `wsock32.dll`

PVZ 1.0.0.1051 的静态导入表只有这些：

```
KERNEL32 / USER32 / WININET / WINMM / WSOCK32 / GDI42 / ADVAPI32 / SHELL32 / ole32 / OLEAUT32
```

选代理目标的三个条件，`wsock32` 全中：

| 条件 | wsock32 | 说明 |
|---|---|---|
| 在导入表里 | ✅ | 游戏启动就会加载它 |
| 不在 `KnownDLLs` | ✅ | 否则永远从 System32 加载，代理无效 |
| 导出少且全具名 | ✅ | 75 条，没有「仅序号」的导出 |

`version.dll` 是网上教程里最常见的代理目标，但**这个游戏不导入它**，放进去也不会被加载。

### 坑：PVZ 是按序号导入 WSOCK32 的

```
#12 ioctlsocket   #16 recv      #116 WSACleanup  #18 select
#9  htons         #111 WSAGetLastError  #23 socket  #52 gethostbyname
#10 inet_addr     #3 closesocket  #19 send      #115 WSAStartup
#151 __WSAFDIsSet #4  connect
```

只导出名字不带序号 → 游戏启动直接 `0xC0000138 STATUS_ORDINAL_NOT_FOUND`。
所以 `gen_proxy.py` 生成的 `.def` 里每条都带原始序号：

```
accept = wsock32_orig.accept @1
```

## 怎么工作

```
游戏目录/
  PlantsVsZombies.exe      ← 一个字节都不改
  wsock32.dll              ← 我们造的代理（230 KB）
  wsock32_orig.dll         ← 真正的系统 wsock32 改名而来（16 KB）
```

加载顺序：

1. 游戏启动，加载 `WSOCK32.dll` → 命中游戏目录里我们的那份
2. 我们的导出表是 75 条 **forwarder**（`名字 = wsock32_orig.名字`），
   加载器自动去加载 `wsock32_orig.dll` 并解析——**没有一行转发代码**
3. 我们的 `DllMain` 起一个线程，跑海克斯逻辑

对外表现：**双击游戏，海克斯就在里面**。没有外部程序、没有第二个窗口、没有注入器。

卸载：删掉这两个文件即可，游戏恢复原版。

## 编译

```bat
dllmod\build.bat
```

依赖：
- MinGW 32 位工具链 `C:\pvztc\mingw32`（`i686-w64-mingw32-g++`，GCC 16.2.0）
- 项目自带的 `.venv`（生成 `.def` 用）

产物在 `dllmod\out\`。

> ⚠️ 工具链的 DLL 必须在 `PATH` 里，否则 `gcc` 会**静默失败**（rc=1 且没有任何输出）。
> 还要加 `-fno-use-linker-plugin`，这台机器没有 `liblto_plugin.dll`。

## 文件

| 文件 | 作用 |
|---|---|
| `gen_proxy.py` | 读 `SysWOW64\wsock32.dll` 的导出表，生成带序号的 forwarder `.def` |
| `src/proxy.cpp` | `DllMain` + 探针线程（里程碑 1） |
| `src/pvz.h` | 游戏内存布局 + 进程内访问器（`Rd` / `Wr` / `Ptr` / `Grab`） |
| `src/log.h` | 落盘日志，写 exe 同目录的 `hextech_dll.log` |
| `build.bat` | 三步：生成 `.def` → 复制真 dll → 编译 |

  - [x] 抽卡：每个对象 1~3 条，按 `apply` 类别过滤，究极档 8% 单掷
  - [x] **互斥组**（4 组，也从 Python 生成）：移速那 6 条互斥，否则叠加起来僵尸会飞

**4 处等效模拟（不是原生机制，如实标注）**

1. 僵尸「攻速」类 4 条（灵巧 / 狂热者 / 孤勇者 / 屹立不倒）—— 用等量**增伤**模拟，
   因为僵尸的啃食间隔字段没定位到
2. 小丑学院 —— 死亡时**原位范围爆炸**，不是真召唤僵尸（`Board::AddZombie` 未逆向，
   硬构造 Zombie 对象会崩）
3. 小小杀手 / 科学狂人 —— 体型只改**碰撞盒**（`+0x10/+0x14`），视觉大小不变
   （reanim 缩放字段没找到）
4. 同一帧多颗豌豆打同一只僵尸会算成一次命中 —— 增伤按比例算，结果基本正确，
   但连续命中判定偏少

> **铁律**：所有「我们自己写进去的血量」都必须同步 `hp_prev`，
> 否则下一帧会把这次伤害当成新的一次命中，增伤反复叠乘 → 无限伤害。
> 外置版 v1.6.3 就是踩这个把僵尸秒了。

> **移速为什么不能直接写 `Zombie+0x34`**（这是外置版踩过、我又差点重踩的坑）：
> `Zombie::Update` 在 `0x52947B` 每帧做 `speed = min(speed + 0.01, target)`，
> `target` 现算。实测 ×2 完全无效、×3 反而更慢（夹回过程占了斜坡）。
> 我一度在进程内测到「写入 +0x34 三秒后还在」，以为不会被覆盖 ——
> 那只是说明游戏没在那几帧重算这只僵尸的速度，**不代表它真的走快了**。
> 判断有没有效只能看 px/秒，不能看字段。
> 正确做法是每帧观测它自己走了多少（`+0x2C` 的差值），再按倍率补一份回去。

> 进程内做这些比外置**简单**：不用每帧过内核读内存，直接解引用；
> 而且跑在 `Board::Update` 开头、每秒精确 100 次，比外置 30Hz 轮询准得多
> （外置要算 `dt`、要低通滤波，进程内这些全都不需要）。

### M3 的工作量说明

`tools/hextech_core.py` 有 2403 行，但其中很大一块是 ctypes 管道
（`ReadProcessMemory` 包装、`struct` 打包、进程扫描）。进程内这些全部消失，
直接解引用即可。真正的逻辑估计在 1200～1500 行 C++。

好处也明显：外置版只能「改数值 + 范围伤害借壳」，进程内可以挂到植物更新里，
做真正的新行为；而且没有每帧过内核的开销。

## 自检与发包

### 离线渲染自检（不开游戏）

```bat
dllmod\build_overlay_test.bat
dllmod\out\overlay_test.exe
```

`test\overlay_test.cpp` 把 `overlay.cpp` 整份 `#include` 进来，就能直接调
匿名命名空间里的 `DrawHp` / `DrawCards` / `DrawPanel`。喂一份假快照画到内存 DC，
输出两张 BMP 到 `C:/pvztc/`：

- `overlay_test_hp.bmp` —— 面板关掉，专看血条层数与词条卡
- `overlay_test_panel.bmp` —— 面板打开，看排版和中文

不开游戏就能核对「血条是不是三层、词条卡的字有没有被格子裁掉、面板有没有乱码」。
本次就是靠它抓到：17px 的卡片里塞 -13 号字，`GetTextExtentPoint32W` 返回的是
**行高**不是字墨高，`(CARD_H - sz.cy)/2` 算出负数，「灵」「力」底部笔画被切。
改成 -11 号字 + 垂直再 -1 才居中。

### 发包（只发 mod，不发游戏）

```bat
python tools\make_dllmod_release.py --version 1.7.0
```

产出 `build\release_dllmod\PVZ海克斯版_dllmod_v1.7.0.zip`，约 0.3 MB，里面只有：

| 文件 | 说明 |
|---|---|
| `wsock32.dll` | 代理本体（我们自己的代码） |
| `一键部署.bat` | 把 DLL 拷进游戏目录；缺 `wsock32_orig.dll` 就从玩家本机系统目录复制 |
| `使用说明.txt` | 安装 / 热键 / 杀软 / 卸载 / 已知限制 |

**为什么不打包整个游戏目录**：`PlantsVsZombies.exe`、`main.pak`（24 MB）、
`images/ reanim/ font/ particles/ data/` 全是 PopCap/EA 的版权素材，
仓库 `.gitignore` 第一条就是「游戏资源不入库」。`wsock32_orig.dll` 是
Windows 系统文件副本，也不该由我们分发 —— 所以让部署脚本从玩家自己的
`C:/Windows/SysWOW64/` 复制。

**`一键部署.bat` 必须保持纯 ASCII + CRLF**：cmd 在 `chcp 65001` 之后是按
**字节偏移**续读批处理文件的，文件里一旦有中文（多字节），偏移就会错位，
把某行的后半截当命令执行 —— 实测会出现 `'克斯本体）复制进游戏目录' is not
recognized as an internal or external command` 这种。中文全放 `使用说明.txt`
（UTF-8 带 BOM，记事本能正常显示）。
